# Contributing

```sh
npm ci
npm run check
```

`npm run check` type-checks with `tsc`, runs the tests with the built-in Node test runner, and rebuilds `dist/`. The test run enforces coverage thresholds of 95% for lines and functions and 90% for branches over `src/`, excluding the entry point `src/index.ts`. Run `npm run test:coverage` on its own to see the per-file report.

## Layout

| Path               | Purpose                                                                     |
|--------------------|-----------------------------------------------------------------------------|
| `src/index.ts`     | Entry point.                                                                |
| `src/main.ts`      | Reads inputs, runs the steps, sets outputs, and writes the log and summary. |
| `src/git.ts`       | Finds the previous tag and lists the release's commits.                     |
| `src/github.ts`    | REST and GraphQL client with retries and rate-limit waits.                  |
| `src/release.ts`   | Finds pull requests and closed issues, then comments and labels.            |
| `src/comment.ts`   | Comment text, the release marker, and the closing-keyword parser.           |
| `src/format.ts`    | Status colors for the log and the summary.                                  |
| `test/helpers.ts`  | Temporary git repositories and the local stand-in for the GitHub API.       |
| `dist/index.cjs`   | The bundled action that runs on the runner.                                 |
| `scripts/`         | Build script.                                                               |
| `.github/linters/` | MegaLinter, Prettier, and markdownlint configuration.                       |
| `.github/codeql/`  | CodeQL configuration.                                                       |

## Tests

The tests use `node:test`, and Node 24 runs the TypeScript directly, so there is no test build step. They need `git` on the `PATH`.

Nothing is mocked below the action's own code. git behavior runs against real repositories created in a temporary directory, isolated from your own git configuration. API behavior runs against a local HTTP server that implements the REST and GraphQL calls the action makes, including pagination, 403, 404, and rate-limit responses.

## Claims and sources

Everything this project says about GitHub, python-semantic-release, or `@semantic-release/github` should be checkable. When changing code or docs:

- Link claims about another project to a file and line at a fixed commit, not to a branch.
- Back claims about this action's behavior with a test.
- Say so when something hasn't been verified. [How it works](how-it-works.md#what-is-not-tested) keeps the list.

## The dist directory

The action runs from `dist/index.cjs`, so commit the rebuilt file with source changes. CI rebuilds it and fails when the committed copy is stale.

`dist/THIRD_PARTY_LICENSES.txt` is generated by [`third-party-notices`](https://www.npmjs.com/package/third-party-notices) (`tpn`), configured in `third-party-notices.config.json`. It covers production dependencies only.

## Docs

Each page under `docs/` starts with a table of contents listing its `##` headings. Update it by hand when a heading changes. MegaLinter fails on a ToC entry or relative link that points at a missing heading or file: markdownlint checks anchors within a page, and lychee checks links and anchors across pages.

## Workflow security

CI audits the workflows with zizmor's pedantic persona. To run the same audit locally, including the online audits, with a GitHub token:

```sh
GH_TOKEN=$(gh auth token) zizmor --persona pedantic .github
```

Every job starts with step-security/harden-runner in `block` mode, so a job that needs a new network endpoint fails until the endpoint is added to its `allowed-endpoints` list.
